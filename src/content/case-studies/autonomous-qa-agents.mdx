## Contexto
El flujo de QA abarca tareas de Jira, casos de prueba, especificaciones de servicios y evidencias de ejecución. Implementé integraciones entre Codex, Postman y Jira para conectar estas actividades con las pruebas web y de APIs.

## Problema
La definición de casos, la consulta de Swagger, la preparación de colecciones y el registro de evidencias se distribuyen entre distintas herramientas. El objetivo del flujo es mantener estas actividades relacionadas con la tarea que se valida.

## Decisiones técnicas
- Utilizar Rovo de Jira para generar casos de prueba a partir del contexto de las tareas.
- Crear especificaciones de Playwright y ejecutarlas con Codex.
- Conectar Codex con Postman y Postman con Jira.
- Usar MCP de Atlassian para consultar y validar la tarea; consultar Swagger mediante otro MCP cuando hace falta.
- Preparar colecciones de Postman para ejecución manual y comparar los datos necesarios para validar los servicios.
- Generar evidencia en PDF y registrar el resultado como comentario en Jira.
- Crear un runner para ejecutar las pruebas en GitLab.

## Arquitectura del flujo
### Pruebas web
Tarea en Jira → casos generados con Rovo → especificaciones de Playwright → ejecución con Codex → evidencia en PDF → comentario en Jira.

### Pruebas de servicios
Tarea consultada mediante MCP de Atlassian → consulta de Swagger cuando corresponde → comparación de datos → colección de Postman → ejecución manual → comentario con resultados en Jira.

### Ejecución en GitLab
Un runner permite ejecutar las pruebas en GitLab, complementando la ejecución local y manual.

## Implementación humana e IA
Mi trabajo incluye crear las especificaciones de Playwright, integrar las herramientas y preparar el runner. Rovo asiste en la generación de casos y Codex en la ejecución de pruebas y la preparación de colecciones y evidencias.

## Resultados
El flujo conecta la definición de casos, las pruebas web y de servicios y el registro de evidencias con las tareas de Jira. Incluye colecciones para ejecución manual y un runner para ejecutar pruebas en GitLab.

## Lecciones aprendidas
La integración debe conservar el contexto de la tarea al pasar entre herramientas. Las pruebas web y de servicios comparten el registro de resultados, aunque sus mecanismos de ejecución son diferentes.
